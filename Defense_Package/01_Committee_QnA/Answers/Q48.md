# Q48 — Gateway đóng gói JSON và xuất bản dữ liệu qua MQTT/TLS như thế nào? Vì sao chọn MQTT thay vì HTTP hoặc WebSocket?

## Trả lời vấn đáp

**Trả lời vấn đáp:** Sau khi giải mã event, Gateway ghép **Patient Event + EnvironmentSnapshot/GPS + RSSI/trạng thái mạng** thành `CompleteRecord`/JSON, rồi **`TaskMqttPublisher`** xuất bản qua **MQTT Broker**; báo cáo mô tả kết nối **TLS**, uplink **Wi-Fi chính hoặc LTE dự phòng**. Dashboard subscribe topic cần thiết để cập nhật không cần gửi yêu cầu HTTP liên tục.

**MQTT** phù hợp gói telemetry/sự kiện nhỏ, pub/sub tách Gateway khỏi nhiều client và dễ tổ chức các luồng topic. **HTTP** chủ yếu request–response; **WebSocket** hỗ trợ streaming hai chiều nhưng nhóm không cần tự xây lớp pub/sub/broker. **Địa chỉ Broker, topic, QoS, retain, session persistence, chứng thư TLS** phải lấy từ file config thực tế; báo cáo không ghi đủ để tự điền.

**Minh chứng nên chèn:** JSON sample đã ẩn khóa/token, topic và log publish/subscribe.
